# v3.0.1-stable 安装与迁移

Windows x64 使用 `cc-unlock-Setup-v3.0.1-stable.exe`。安装前退出旧 cc-unlock 部署工具，防止可执行文件占用；这不表示上下文清理要求关闭 Codex。工具不包含原版 Claude / Codex 客户端。对话编辑需要 Python 3.10+，可用 `CC_UNLOCK_PYTHON` 指定解释器绝对路径。

## Claude：原版 Desktop + CLAUDE.md

1. 使用原版 Claude Desktop 的 Code 标签页，不再从旧 companion 启动自定义客户端。
2. 在 cc-unlock Claude 工具中选择实际工作区；部署内容仅为工作区 `CLAUDE.md` 和 `sec-forge` skill。
3. 原有 `CLAUDE.md` 若包含需要保留的项目约定，先合并；命令行默认拒绝覆盖不同内容，明确替换时使用 `-Force` / `CC_UNLOCK_OVERWRITE=1`。
4. 新建 Code 会话，验证工作区指令是否被读取。不得用旧会话快照代替新请求的证据。

```powershell
.\cc-unlock-files\deploy.ps1 -Path 'C:\path\to\workspace'
.\cc-unlock-files\deploy.ps1 -Path 'C:\path\to\workspace' -Verify
```

脚本要求 PowerShell 5.1+。可加 `-SkipSkill` 仅部署/检查 `CLAUDE.md`。`-SkipSettings` 为兼容参数；当前最小部署始终不改全局 Claude settings。macOS / Linux 保留明确路径的 shell 部署入口，不代表已提供本版桌面安装器：

```bash
bash ./mac-install.sh /path/to/workspace
bash ./mac-install.sh --verify /path/to/workspace
```

## 旧数据

不再部署 memory、agents、rules、agent-memory 或 Codex rollout。已有个人文件不会被按名称删除；旧版同名文件可能含个人修改，需先核对来源和内容。此版本不是个人数据清理器。

## Codex

Codex 与 Claude 单独部署；命令行需显式 `-Codex` / `--codex`。部署保留 prompt/config/skills 与“修改对话”，不部署或删除个人 memory/rollout 摘要。

在 Codex 工具选择“一键清理历史指令”，不必先扫描或退出 Codex。锁目录按当前用户主目录解析为 `~/.codex/thread-writer-locks`，固定先删除其中所有文件（含隐藏/子目录文件，保留目录），再置空命中旧 Collaboration Mode 模板的 developer 指令 token；不删除对话、用户/助手消息或 SQLite。不以运行中或未知状态为跳过锁清理的条件，实际删除失败如实报告。运行中的 Codex 之后可能重建锁，此操作不是持续守护。

该操作只改磁盘历史。已打开任务的内存上下文不会立即变化，应重新加载并核对实际指令。并发追加保留；文件/目标变化或读写失败会显示部分完成。删锁不意味着获得独占写入，同一目标位置仍有比对到写入之间的竞争限制。

`sec-forge` 技能工具要求 Node.js 20+；当前锁定构建依赖要求 Node.js 22.12+。新部署包含 `win-reverse` 0.3.0、`web-reverse` 0.1.1；详细源码构建与 NSIS 配置见 [README](../README.md)。

## 卸载工作区配置

```powershell
.\cc-unlock-files\deploy.ps1 -Path 'C:\path\to\workspace' -Uninstall
```

```bash
bash ./mac-uninstall.sh /path/to/workspace
```

只移除与当前包内容一致的 `CLAUDE.md` 和 skill 文件。修改过的正文、个人记忆、子 agent、规则、全局 settings 保留。旧的批量 `-All` / `--all` 已禁用，须提供明确路径。
