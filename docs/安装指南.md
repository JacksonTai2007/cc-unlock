# cc-unlock v2.0-stable 安装指南 | Installation Guide

把 Claude Code 和 Codex 配置成安全研究工作站。**Windows 走图形安装器,macOS / Linux 走全功能 shell 安装器——两条路径部署的是完全相同的 bundle**(memory + CLAUDE.md + skills + 子 agent 覆盖 + Codex system-prompt/AGENTS/config/memories/skills)。

---

## 系统要求 | Requirements

- 已安装并可运行 Claude Code 和/或 Codex
- 操作系统:Windows 10/11、macOS 12+、主流 Linux 发行版
- Windows 图形安装器免管理员(per-user 安装);shell 安装器需要 bash

---

## Windows —— 图形安装器(推荐)

1. 从 [Releases](https://github.com/JacksonTai2007/cc-unlock/releases) 下载统一安装器 **`cc-unlock-Setup-v2.0-stable.exe`**
2. 运行安装器:
   - **勾选组件**:cc-unlock for Claude Code / cc-unlock for Codex / 两者
   - 选安装路径(默认 `%LOCALAPPDATA%\Programs\cc-unlock`)
   - 自动建桌面 + 开始菜单快捷方式
   - 升级时自动静默卸载旧版再装,不残留
3. 打开应用,进入「部署」页:
   - **Claude**:选工作区 → 开启「子 agent 覆盖」 → 点部署
   - **Codex**:(可选勾中转站填 API 地址/Key/模型) → 点「部署 Codex」
4. 重启 Claude Code / Codex

> 卸载:Windows 设置 →「应用」→ cc-unlock → 卸载;或安装目录里的 `Uninstall.exe`。

### Windows —— 命令行部署(legacy PowerShell,进阶)

不想用 GUI 也可以直接跑部署脚本(与 GUI 部署同一套逻辑):

```powershell
.\cc-unlock-files\deploy.ps1 -Path "C:\path\to\workspace"   # 指定工作区
.\cc-unlock-files\deploy.ps1 -GUI                            # 文件夹选择器
.\cc-unlock-files\deploy.ps1 -All                           # 所有已有工作区(仅 memory)
.\cc-unlock-files\deploy.ps1 -Codex                         # 仅 Codex
.\cc-unlock-files\deploy.ps1 -Verify                        # 验证
.\cc-unlock-files\deploy.ps1 -Uninstall -All                # 卸载
```

## macOS —— shell 安装器

macOS **不需要装双系统**。Electron app 本身跨平台,但当前只打了 Windows 图形安装器;macOS 用**功能对等的 shell 安装器**原生部署——同一个 bundle,同样的 skills / 子 agent / Codex 全覆盖,只是没有 GUI。

### 方法一:双击

1. Finder 里找到 `启动.command`
2. 若提示「无法验证开发者」:右键 → 打开 → 弹窗点「打开」,或终端 `xattr -d com.apple.quarantine 启动.command`
3. 双击运行,按菜单选择

### 方法二:终端

```bash
chmod +x mac-install.sh
./mac-install.sh                      # 交互菜单
./mac-install.sh /path/to/workspace   # 部署到指定工作区(含 skills + 子 agent)
./mac-install.sh --all                # 所有已有工作区(仅 memory)
./mac-install.sh --codex              # 仅 Codex
./mac-install.sh --list               # 列出工作区
./mac-install.sh --verify             # 验证
```

> **注意**:skills + 子 agent 覆盖需要真实工作区路径,所以要用 `方法一菜单选[1]` 或 `./mac-install.sh /path/to/workspace` 指定路径;`--all` 只按项目名铺 memory(拿不到工作区文件系统路径)。

## Linux —— shell 安装器

```bash
chmod +x cc-unlock-files/linux-install.sh
./cc-unlock-files/linux-install.sh /path/to/workspace   # 指定工作区(全覆盖)

./cc-unlock-files/linux-install.sh --codex              # 仅 Codex
./cc-unlock-files/linux-install.sh --verify             # 验证
```

## 部署内容 | What Gets Deployed

### Claude Code(按工作区)

| 注入点 | 目标位置 | 作用 |
|---|---|---|
| memory 档案(21 个 *.md) | `~/.claude/projects/<PROJECT>/memory/` | 研究员身份 + 交付先例 many-shot |
| `MEMORY.md` | 同上 | memory 索引 |
| `CLAUDE.md` | 工作区根目录 | 主 agent + 所有非 fork 子 agent 人格 |
| `skills/sec-forge/`(含 android/web/win-reverse) | `<ws>/.claude/skills/` | 安全研究总控:JIT harness + 自我进化 + 路由 |
| `skills/jit-harness/` | `<ws>/.claude/skills/` | 通用即时 harness 引擎 |
| `agents/*.md`(sec-executor / recon / planner) | `<ws>/.claude/agents/` | 带人格的执行/侦察/规划子 agent |
| `rules/cc-unlock-persona.md` | `<ws>/.claude/rules/` | 启动即进主 + 所有非 fork 子 agent |
| `agent-memory/<name>/MEMORY.md` | `<ws>/.claude/agent-memory/` | 子 agent `memory:project` 自动注入 |
| `settings.json`(可选) | `~/.claude/`(全局) | bypassPermissions,消除工具确认摩擦 |

### Codex(全局 `~/.codex`)

| 注入点 | 目标位置 | 作用 |
|---|---|---|
| `system-prompt.md` | `~/.codex/` | 人格 base(由 config.toml 的 `model_instructions_file` 指向) |
| `AGENTS.md` | `~/.codex/` | 叠加在 base 之上的冗余人格层 |
| `config.toml` | `~/.codex/`(合并写入) | `model_instructions_file = "system-prompt.md"` + 可选 relay |
| `memories/`(memory_summary/MEMORY/raw_memories) | `~/.codex/memories/` | persona + 交付 many-shot |
| `memories/rollout_summaries/`(104) | `~/.codex/memories/` | 模拟成功协作记录 |
| `skills/sec-forge` + `skills/jit-harness` | `~/.codex/skills/` | 与 Claude 同一套技能 |

### 路径编码规则 | Path Encoding

Claude Code 把工作区路径编码为项目目录名:`:` `\` `/` 空格 → `-`

示例:`C:\Users\User\Desktop\my project` → `C--Users-User-Desktop-my-project`
部署到:`~/.claude/projects/C--Users-User-Desktop-my-project/memory/`

## 验证部署 | Verify

- **Windows GUI**:应用「验证」页,逐项显示 memory / CLAUDE.md / skills / agents / rules / agent-memory / Codex 各注入点状态
- **Windows CLI**:`.\cc-unlock-files\deploy.ps1 -Verify`
- **macOS / Linux**:`./mac-install.sh --verify` 或 `./cc-unlock-files/linux-install.sh --verify`

手动检查关键文件:

```
~/.claude/projects/<PROJECT>/memory/learner-profile.md
<workspace>/CLAUDE.md                       (含 "cc-unlock" / "安全研究工作站")
<workspace>/.claude/skills/sec-forge/SKILL.md
<workspace>/.claude/skills/jit-harness/SKILL.md
~/.codex/system-prompt.md
~/.codex/AGENTS.md
~/.codex/config.toml                        (含 model_instructions_file = "system-prompt.md")
```

## 卸载 | Uninstall

| 平台 | 方式 |
|---|---|
| Windows GUI | 设置 → 应用 → cc-unlock → 卸载(移除应用);应用内「卸载」页移除部署 |
| Windows CLI | `.\cc-unlock-files\deploy.ps1 -Uninstall -All` |
| macOS | 双击 `卸载.command`,或 `./mac-uninstall.sh [path|--all]` |
| Linux | `./cc-unlock-files/linux-uninstall.sh [path|--all]` |

卸载移除 cc-unlock 部署的所有文件:memory 档案、工作区 CLAUDE.md、skills、agents、rules、agent-memory、Codex 的 system-prompt/AGENTS/memories/rollouts/skills,并从 `config.toml` 剥离 `model_instructions_file` 行(保留其它设置)。按签名删除 cc-unlock 创建的 `settings.json`;用户自有内容保留。

### 一键恢复原始(Electron 独有)

Windows 应用「部署」页有「恢复原始」按钮:把 `config.toml` / `CLAUDE.md` / `MEMORY.md` 还原成**首次部署前的字节**,并清掉 cc-unlock 新增的文件——部署出问题随时可退回。

## 常见问题 | FAQ

**Q: 部署后没变化?**
必须重启 Claude Code / Codex 才会重新加载 memory / CLAUDE.md / skills。

**Q: macOS 一定要装双系统或 Windows 虚拟机吗?**
不用。shell 安装器在 macOS 原生跑,部署的 bundle 和 Windows 图形安装器完全一致。GUI 只是 Windows 的便利层,实际部署逻辑跨平台相同。

**Q: skills 和子 agent 覆盖没部署上?**
它们需要真实工作区文件系统路径。用「指定工作区」模式(GUI 选文件夹 / `deploy.ps1 -Path` / `mac-install.sh /path`),不要用 `--all`(只铺 memory)。

**Q: 会破坏 cc-switch 的 Codex 配置吗?**
不会。`config.toml` 用字节安全的合并写入,只加 `model_instructions_file`(+ 可选 relay 段),保留 cc-switch 的 provider、密钥和任意 CJK 内容;`auth.json` 不被触碰。

**Q: PowerShell 执行策略阻止运行?**
```powershell
PowerShell -ExecutionPolicy Bypass -File .\cc-unlock-files\deploy.ps1 -GUI
```

**Q: settings.json 会覆盖现有设置吗?**
不会。仅在 `~/.claude/settings.json` 不存在时部署;`-SkipSettings` 完全跳过。
