# v3.0.1-stable 运行机制

```text
prompts/claude.md
  → sync-prompts
  → cc-unlock-files/claude-config-bundle/CLAUDE.md
  → 选定工作区/CLAUDE.md
  → 原版 Claude 的工作区指令加载

cc-unlock-files/skill-bundle/sec-forge
  → 选定工作区/.claude/skills/sec-forge
```

部署不再修改 Desktop ASAR、内置 CLI、systemPrompt 或进程环境。CLAUDE.md 是工作区指令，不是客户端系统提示词的完全替代品。

Claude 只部署一个主提示词和 sec-forge；不创建 memory、agents、rules、agent-memory，不设置全局权限配置。Codex 部署 `prompts/codex-system.md` 与 `prompts/codex-agents.md` 对应的 system-prompt/AGENTS 载体及 sec-forge，不注入或删除个人 memory/rollout 摘要。

## Codex 历史字段清理

清理与提示词部署是独立操作。工作进程直接读取 `sessions` 和 `archived_sessions` 中的 rollout，识别旧 Collaboration Mode 模板的 developer 指令字段；普通用户/助手消息中的引用不作为目标。无需先扫描，不以 Codex 正在运行为拒绝清理的条件。

锁目录从当前用户主目录动态解析为 `~/.codex/thread-writer-locks`，固定先删除其中所有文件（含隐藏和子目录文件，保留目录），再处理匹配指令 token；不要求 Codex 退出，不以进程活动/未知状态跳过锁清理。删除失败如实记录；运行中的 writer 后续可能重建锁。字段变更采用等长定位写入，不整文件替换或截断，从而保留行结构、偏移和并发追加。不会删除消息、对话或 SQLite，不在上下文清理中修复 lineage。源文件身份、长度及目标内容出现冲突，或实际读写失败时报告部分完成。

磁盘历史修改不等于热更新已载入的上下文；`diskOnly` 为真，当前任务需要重新加载。删锁不取得独占写入，乐观比对无法原子阻止同一目标位置在最终检查后的竞争写入，结果不是任意并发改写的无损保证。

## 技能与验证预算

`sec-forge` 绑定当前对象和验收条件，不新增目标或宿主权限。普通文本/config 不默认哈希；定向检查复用仍有效证据。Windows 子技能 0.3.0 去除特定软件硬编码与重复完整性检查；Web 子技能 0.1.1 用宿主实际技能路径定位工具，并根据当前浏览器工具文档选择 API，不每轮重复环境预检。

部署范围由用户选择的工作区路径确定。历史项目 ID 不能可靠逆推工作区，因此 legacy 批量部署入口已停用。用户资料与旧部署可能混合，不能以同名为删除依据。

主提示词约定任务目标、验收条件、证据记录和有界修复；安全分析按实际对象使用对应 skill。授权上下文与服务端拒绝理由分开记录，不把所有失败归为缺少授权，也不承诺提示词能更改服务端策略。
