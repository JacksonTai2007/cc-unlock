# v3.0.1-stable 提示词说明

Claude 使用原版客户端和 `CLAUDE.md`；Codex 继续使用自己的部署入口。不按模型名称硬编码切换文本，也不强行改变用户选择的模型。

共同方法：先定义目标与验收条件，读取相关输入，执行可行步骤，保留实际输出，依据证据修复。已提供的授权材料作为上下文保留；缺少技术参数时询问具体参数，不反复索要同一证明。

提示词应使用准确技术名称和限定范围，不把生产目标改称实验室，不用替代术语掩盖实际行为。不承诺“脱敏后必过”或“关闭 safeguard”。客户端部署测试不等于真实模型误拒绝率评测。

安全研究的具体方法由 `sec-forge` 和 Android/Web/Windows 子工作流提供；只有实际存在并读到的技能才算加载成功。JIT harness 直接包含在主提示词中。

`sec-forge`、Windows 0.3.0 和 Web 0.1.1 更新的是对象路由、工具定位、能力确认和验证预算，不是特定模型的拒绝处理接口。普通配置/文本不默认计算哈希，已通过且输入未变的证据复用。

上下文清理也不是模型适配接口：Codex 运行中可按固定顺序删除当前用户主目录下 writer 锁目录内所有文件（目录保留），再修改匹配历史指令 token；不根据进程状态跳过删锁，writer 后续可能重新建锁。用户/助手消息和 SQLite 保留，但不会热替换当前已加载上下文。需重新加载任务；删锁不取得独占写入，同一目标位置的并发竞争与真实工具错误如实记录，不解释为缺少授权。

新会话评测应记录实际模型、设置、输入和可见结果。只有合成客户端测试时，不声称真实模型效果提升。
